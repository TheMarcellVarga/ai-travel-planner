# Next.js Travel UI

## Use When
- Editing App Router pages.
- Building planner UI.
- Updating route cards, saved routes, account UI, public share pages, header, or footer.
- Improving responsive behavior or visual polish.

## Rules
- Follow root `AGENTS.md`, `app/AGENTS.md`, and `docs/DESIGN_SYSTEM.md`.
- Preserve the jungle/adventure/editorial direction.
- Keep the planner usable without the globe.
- Mobile is first-class.
- Show loading, empty, and error states.
- Use accessible labels, focus states, and text-visible confidence/error states.
- Do not move domain logic into UI components.

## Verification
- Run relevant tests.
- Build if framework behavior changed.
- Browser-check the affected route when possible.
- Check mobile layout for planner, route cards, and share pages.
